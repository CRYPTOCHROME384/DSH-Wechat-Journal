# 与 Notion 双向同步

## 一句话

**只有字段双向，正文永不回写。**

## 为什么划这条线

Markdown ↔ Notion blocks 的往返是有损的。表格、嵌套列表、callout、行内代码，
过去再回来就会变形。一旦让正文双向，第一次同步就会把你写的东西改形——而且改完
你未必立刻发现。

所以分三类：

| 内容 | 方向 | 理由 |
| --- | --- | --- |
| 任务（状态/日期/项目/备注） | **双向** | 纯字段，往返无损 |
| 文献条目（状态/tag/我的批注） | **双向** | 同上 |
| 标题、摘要、周报正文 | 本地 → Notion 单向 | 机器生成，不需要回写 |
| 项目页四问 | 本地 → Notion 单向镜像 | 机器维护，避免两处改 |
| `notebook.md` | **不参与** | 纯个人写作，只留在本地 |

**单向镜像页顶部有横幅：「由账本生成，别手改」**。真被手改了也不覆盖——
检测到就报冲突，让你选。

## 冲突规则：三方比较，永不自动合并

每次同步记三样东西：上次同步的快照、本地现在的值、Notion 现在的值。

| 情况 | 处理 |
| --- | --- |
| 只有本地变 | 推到 Notion |
| 只有 Notion 变 | 拉回本地 |
| 两边都变 | **不合并**。写进待判，你选留哪个 |
| 镜像页被手改 | 报冲突，不覆盖 |

自动合并是双向同步最常见的死法：它会把两个都合理的改动揉成一个都不对的版本，
而且你看不出它揉过。

## 状态文件

```
journal/sync-map.json     每条记录的 notion_page_id ↔ local_id
                          + last_synced_at + 上次快照
journal/sync-log.jsonl     每次同步改了什么（只追加）
```

**这两份是同步的全部记忆。** 删了它，系统就不知道谁变过——所以它比代码重要。

## 幂等

同一份数据同步两遍，结果必须一样；中途失败重试不能产生重复页面。
做法：先按 `sync-map.json` 找页面 id，找不到才新建；新建后立刻落 map。

## 前置条件（缺一不可）

1. **代理常开** —— 现在 `127.0.0.1:7890` 没有任何进程监听，出网全断。
   Notion API 走 HTTPS，没有代理我连不上。
2. **integration token** —— Notion 里建一个 internal integration，把目标页面
   「连接」给它。token 存本地，不进 git。
3. **数据库字段结构** —— 我需要知道你那两个库的**属性名和类型**（title / select /
   date / rich_text…）。字段名对不上，映射就是猜的。

## 不做的事

- ❌ 不做实时同步。按需触发，或每晚一次。
- ❌ 不做双向正文同步。
- ❌ 不做自动合并。
- ❌ 不在 Notion 里建本地没有的结构（两套模型会互相拉扯）。
